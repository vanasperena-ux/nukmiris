## Calendar/time/reminder boundary

Juanita example: Mexico City, Monday–Friday 10:00–19:00, 60-minute starts/duration, zero buffer, lunch 13:00–14:00. Future empty weekday starts: 10,11,12,14,15,16,17,18. Default discovery 30 days then 15-day increments for three available dates, max 365 business-local civil days; selected dates/final slot checked directly. Failed/malformed/partial/pagination-loop response never means free. Nonexistent DST times rejected; repeated-fold behavior must match observed Luxon/source fixture before any deliberate policy change. No new arbitrary fold omission. Persist actual instants plus zone/policy/tzdata version.

Original raw WhatsApp subject remains identity; outbound/display normalization does not merge verified identities. Reminders default off; dry-run can preview without proactive sends **or attendance writes**, while ordinary booking/move/cancel still operate in their own authorized mode. Live remains disabled absent separate approval. Preserve new post-activation app-intent enrollment, exact strictly future offsets 168/24/22/2 elapsed hours, 15-minute late submission allowance before start, no catch-up, first-processing skip of follow-up if delivered/read parent not yet established. Exact template text/buttons/names/language remain in pinned REMINDER_TEMPLATES; caps 900/900/900/300 seconds, fresh actual WABA/sender checks, permission, TTL+transport-before-start. These contract checks are not fresh Meta approval evidence. Attendance `Sí, confirmo` is pre-appointment confirmation, not proof of eventual attendance. No-response never cancels. Move/cancel/manual observation invalidates current schedule actions as implemented; current confirmed-manual-move enters review. Current matching quoted/generic reply history retained. No new consent question or survey in P0. Preserve the optional reminder sentence only when actually eligible in live mode; never promise it in off/dry-run.
