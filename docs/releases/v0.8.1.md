- Standalone booking and management reconciliation now commit eligible reminder metadata using the same existing transaction hooks as the running app. Repeating recovery does not duplicate schedules or send reminders merely because the command runs.

- Exactly **403** audited main-file lines were removed: 398 unreachable tail lines and five unused bindings. One unused test import name was also removed. Seven stopping stubs, retained callers and the dispatcher remain unchanged.
- The remaining B01–B19 legacy candidates are assessed for separately authorized future work. No further candidate code is removed.
- Package and lockfile labels now say **0.8.1**. At PR #1's merge the label still said 0.8.0; correcting it changes no executable behavior or dependency version.

## Updating an already prepared PC

This guide applies to the owner's working v0.8.0/maintenance installation. Preserve local changes and stop Node before updating. From the existing repository's `backend` folder in PowerShell:

```powershell
git status --short
git fetch origin
git switch main
git pull --ff-only origin main
node -p "require('./package.json').version"
```

Expect **0.8.1**. Existing credentials, selected business/calendar, database, pending requests/jobs and `.env` remain in place. This release adds no dependencies or schema, and requires no new reminder preparation, data clearing, token reset or Google/Meta reconnection. Follow Git's local-change protections rather than forcing an overwrite.

The owner has already completed the functional checkpoint. Updating the version label/documentation alone does not require another manual booking round. The complete automated command, whenever needed, remains:

```powershell
npm.cmd test
```

Expect **1,089 passed**, zero failures/cancellations/skips. Start the normal app with its existing settings using:

```powershell
npm.cmd start
```

Reminder behavior remains off/dry-run unless the owner separately activates live sending after the existing permission/WABA/template checks. This maintenance release does not submit templates, obtain consent, edit existing Calendar events, import old appointments or activate production reminders. The Services Catalog and hosting remain separate future work.
