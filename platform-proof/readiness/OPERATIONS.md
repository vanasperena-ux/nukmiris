# G-3 source review and future account receipt obligations

## Corrections and trust boundaries

H-3: retirement now includes any record/link carrying the retired epoch **or** retired revision when its counterpart is missing/conflicting. Authenticated but ambiguous attribution yields HOLD; exact authenticated old post-fence initiation yields VIOLATION even if another activity or nonfatal metric/canary gap is unresolved. Authentication/chain failures still HOLD. `provider-identities.mjs` rejects incomplete/unapproved certificate→epoch/revision mappings before the fake listener or mounted fake profile is accepted. Observer certificates cannot acquire gateway claims. Caller binding headers cannot override authenticated client-certificate identity. Correct complete realistic V2 fixtures remain required to pass.

`PreparedTerraformTeardown` restores pending exact destroy intents from a hash-chain-verified journal before action. Its journal must itself be backed by independently retained custody/checkpoint authority (hash-chain integrity alone is not independent authorship or extension proof). A restart cannot issue another destructive call for an unresolved intent. Missing Terraform state alone never establishes resource absence: the exact original cloud resource must have an independent typed API read receipt. Permission failure, replacement/unknown identity, corrupt history, missing original state, journal failure or ambiguous readback keeps cleanup unresolved. A successful absence record closes the original intent; it does not prove Cloud Run instance death. No cleanup retries invent a replacement identity.

`independentAuthorityPlan(plan, 'KILL'|'CLEANUP')` exposes only approved role operations/grants, without constructing a full deployer-dependent controller. Kill includes independent old-tag denies, exact secret/decrypt withdrawal, revision deletion and whole-service/worker deletion. Cleanup is separately scoped and does not borrow deployer. The same sole human may impersonate them under separately verified access; these are different technical principals, **not independent human custodians**. One unavailable/compromised human can defeat supervision, custody and billing response. This accepted owner risk is not solved by adding service-account names.

## Future read-only account verification, not executed here

The machine-readable [schema](account-receipts.schema.json) and [null template](account-receipts.template.json) require exact organization/policy administrator, all-traffic/no-VPC bypass policy, runtime/custody/fake project IDs/numbers/parents, APIs/quotas/SKUs/region, SQL tier/edition/privateTLS/roles/connections, candidate digest, billing account/currency/current owner-approved FX, trial eligibility/expiry/no-upgrade, exact bounded session, named sole operator/common-human risk/duties and four distinct deployment/kill/cleanup/custody-cleanup identities. Each future evidence source needs an authorization reference, freshness and source digest. Effective role/impersonation receipts must show direct human access to kill/cleanup without the deployment identity and cleanup control survives deletion of experiment-managed identities/projects. No operator name/email/account value is invented now.

`validateAccountReceipts` rejects missing/stale/mismatched values; even structurally valid JSON returns `runtimeReady:false`, `actualAccountVerified:false`, `provisioningAuthorized:false`. JSON booleans and source hashes are not authentic cloud evidence. Separately authorized read-only verification and independent review must authenticate the underlying receipts before any resource-specific provisioning proposal. `validateInputs(...PROVISIONING_PLAN)` requires the offline schema; LIVE=false and impossible Terraform guard still prohibit execution. Local fixture bypass is explicitly synthetic and cannot start a live transport.

`cleanupReceiptChecklist` creates one NOT_EXECUTED slot for **all140** inventory addresses in dependency-safe reverse order, with original ID, role, deletion receipt, independent read, retention and follow-up. It covers the full Terraform inventory, beyond the short emergency command list. Nondeletable KMS rings/keys require key-version retirement receipts plus explicitly accepted metadata residuals and eventual separately authorized project disposal. Billing-budget get/delete is manual billing-account owner action, never claimed by a project-only IAM grant. Account receipt and resource deletion status remain null/NOT_EXECUTED until real evidence exists.

On session expiry/operator absence: stop renewal, durably hold SQL when available; revoke/fence/request independent deletion. SQL expiry protects new entries even when the supervisor is down. It cannot stop an already authorized frozen process or prove all buffers drained; unresolved original attempts remain protected and do not resend. Cleanup interruption resumes by original authenticated journal/state binding and read-only observation; no broad project purge or implicit resource recreation. Follow-up at+2h,+48h,next statement remains necessary even if immediate inventory is clear.
