# G-2 authenticated transit observations and a held experiment

## What is implemented

`runtime/transit-evidence.mjs` validates `INDEPENDENT_TRANSIT_MEASUREMENT_V1`. The separately controlled probe signs ACTIVITY with a pinned Ed25519 key. The independently administered observer uses a different pinned key to sign the full mTLS-exported fake ledger and calibrated V2 CLOCK observations. Expected trust pins, certificate fingerprints, session/scope, gateway epoch/revision and provider identity are supplied outside the evidence bundle. An HTTP field cannot register a key. Ledger checkpoint/hash-chain and exact export digest are verified before use. Partial/forged/stale/misattributed evidence holds.

`runtime/transit-probe.mjs` is a bounded, local synthetic measurement sender, not a dispatch permit or a cloud transport. It accepts literal loopback LOCAL_SIMULATION only and exactly `{synthetic:true}`; one fresh TLS connection, one write, no retry. A private in-process receipt brand permits its independent signer to attest actual probe phases. The fake's certificate authenticates server identity; the epoch-specific client certificate authenticates the sender. IPC secrets and test certificates are ephemeral and excluded from the image/evidence. A future cloud probe requires a separately reviewed implementation/authorization, not changing a mode string.

Phases are CONNECT_BEGIN, TCP_CONNECTED, TLS_ESTABLISHED, WRITE_BEGIN, WRITE_END. Wall timestamps and per-process monotonic nanoseconds are preserved. The provider independently records TLS_READY and REQUEST arrival. Exact attempt/operation/scope/payload digest, authenticated epoch/revision/certificate, socket local-to-remote port and connection ID bind the records. Provider EFFECT records remain in the full authenticated export. No phase is inferred from gateway self-reported traces.

The WRITE_END timestamp is the Node write callback: local buffer acceptance, **not wire transmission or provider receipt**. TCP/TLS readiness is not a request write. A signed sender write after a fence is conclusive for that controlled probe even on a connection established before the fence. A pre-fence write arriving after the fence is preserved as pre-fence initiation plus delayed arrival; it is not mislabeled a new send. Delays widen intervals or exceed the hypothesis; they never justify unsafe resend.

V2 four-timestamp calibration supplies offset intervals, declared drift, timestamp precision, resynchronization allowance and bounded extrapolation. Phase/provider/fence times are conservatively correlated. Disjoint chronology or uncertain overlap holds. Observed delivery interval is `[max(0, arrival.lower - WRITE_END.upper), max(0, arrival.upper - WRITE_BEGIN.lower)]`. This is an observation of one flow, not an assertion about all unobserved buffers. Clock allowances and independent control remain declared local test assumptions, not proven cloud oscillator bounds.

The ten charter scenarios map to `readiness-transit.test.mjs` and `readiness-native-transit.test.mjs`. Native evidence freezes a separate process **at the instrumented post-TLS point**, verifies Linux stopped state, declares a fence, resumes and releases a post-fence write on the same socket. This is not arbitrary-instruction suspension or actual Cloud Run termination. The independent fake server continues running and records TLS/REQUEST/EFFECT. Separate tests cover long pre-fence-write/late-arrival, wrong provider/session, forged evidence, missing phases, clock overlap, late/unobserved canary wake and absent/exceeded candidate bound.

## No universal bound / no synthetic containment claim

A finite maximum, a TCP retransmission timeout, firewall new-flow deny, Cloud Run request timeout, API DELETE/404, CPU throttling, an expiring lease or absent recent logs does not prove that all buffered or frozen old-instance sends are impossible. An established connection can survive the firewall change; a paused sender may write later. Unbounded observation/reporting loss also prevents a finite inference. Twenty local canaries and a 60-second target do not convert these assumptions into guarantees.

A trustworthy finite bound would require independently reviewed platform guarantees over every relevant sender, established flow and buffer, authenticated capture/connection attribution at a trustworthy observation boundary, bounded and separately measured clock uncertainty, and conclusive physical old-instance termination plus coverage of delayed provider application. Google platform behavior must be measured separately from Monitoring's sampling/publication latency. No such complete cloud guarantee is established here. The existing measured transit policy remains LOCAL_SIMULATION-only and cannot be renamed into cloud evidence.

A valid sample returns **COLLECTED**, `usableAsRetirementPolicy:false`, `containmentProven:false`. `transitCollectionGate` always returns HOLD, dispatch/promotion false, automatic resend false, new identity false. An authenticated post-fence initiation returns VIOLATION and requires abort/independent kill, even if unrelated evidence is incomplete. This protocol mints no retirement capability. Existing V2 retirement/reconciliation/promotion gates still require authenticated complete evidence and the original accepted local policy; actual cloud enablement remains blocked by source and cannot use this sample as a substitute.

2. Start dispatch HELD. Prepare independent custody, observer/probe pins, synthetic fake-only destination, bounded session/expiry and separate kill/cleanup access. Keep general gateway promotion HELD.
3. Under an explicit bounded synthetic-probe authorization, collect labeled connect/TLS/write/arrival/clock/network/instance observations. Preserve all delayed, frozen, preexisting-connection and incomplete cases; no automatic retry or replacement operation IDs.
4. Sample each candidate hypothesis without declaring a bound certified. Preserve signed raw exports and independent heads. Missing/delayed metrics are not zero. A late wake must be observed or remain HOLD.
5. On uncertainty, expiry or violation, stop renewal, hold SQL, fence new flows and request independent service/revision/worker deletion; retain established-flow uncertainty until independently resolved. One human may be unavailable: database expiry prevents new permits, but a frozen previously authorized process still requires physical termination proof.
6. Export evidence, perform exact teardown and residual/billing follow-up. Never recover/promote/resend based solely on a measured maximum. Seek independent review and a later design decision if a finite platform guarantee remains unavailable.

These are proposed test obligations, not an executable cloud entry point or owner authorization to run them.
